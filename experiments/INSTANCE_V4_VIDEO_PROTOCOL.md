# Дополнение для нового видео до оценок

DAVIS 2017 trainval 480p с официального сайта:
https://davischallenge.org/davis2017/code.html.
Источник указывает CC BY-NC 4.0 для набора в метаданных сайта; новые
аннотации CC BY 4.0 (правила challenge2017). Материалы используются для
некоммерческого исследования, локально, с цитированием обеих статей
DAVIS 2016 и 2017. Видео не включаются в Git.

Берутся первые 20 названий по алфавиту из официального ImageSets/2017/val.txt.
Они все являются новым тестом нашего проекта; на DAVIS не обучаются MLP
и не выбираются пороги. Название val в источнике не означает нашу валидацию.
Пересечение с предобучением больших моделей неизвестно. Идентичность
аннотирована внутри последовательности, глобальное непересечение физических
объектов между всеми съёмками не гарантируется. Bootstrap/агрегация — по видео.

В каждом видео выбрать до двух первых ненулевых ID первого кадра (255 void
исключается). Единственный референс — RGB-вырезка минимальной прямоугольной
рамки маски этого ID в первом кадре, без удаления фона. Первый кадр исключить
из оценки. Это протокол эталона той же сцены; он не подменяет отдельную съёмку
RGB-D. Детектор получает только референс и следующие кадры, не первую рамку
в координатах видео и не маски последующих кадров.

Основная оценка полных кадров — 8 равномерных позиций среди оставшихся кадров
каждого видео (если меньше 8 — все). Дополнительно для первых двух видео
обработать все кадры, чтобы получить последовательную демонстрацию потери
и восстановления. Дополнительные кадры не добавляются в основную сводную
таблицу 20 видео, их метрики приводятся отдельно.

YOLOv8n, imgsz640, conf0,25, NMS0,45, max_det20 — общие кандидаты. Выбрать
ближайший DINO-косинусом. Три метода: исходный визуальный, ужесточённый
визуальный, условный текстовый MLP seed2027/полный Махаланобис. Пороги
перенести из RGB-D validation без изменения. Текст описывает только
референсы и кандидатов, запрос которых предусмотрен зафиксированной политикой.
Отсутствие описания — возврат к визуальному решению.

Рамка GT строится из видимых пикселей маски: [xmin,ymin,xmax+1,ymax+1].
ID отсутствует в маске — нет видимой аннотированной цели, не доказательство
физического отсутствия за перекрытием. TP требует IoU≥0,5; неправильная рамка
при наличии цели даёт FP+FN. Чужой экземпляр отдельно отмечается только
при IoU≥0,5 с рамкой другого размеченного ID. Иные ошибочные рамки — не
автоматически подтверждённое принятие чужого физического экземпляра.

Средний IoU по присутствиям включает нули пропусков; absence FPR даётся
только при наличии кадров отсутствия. Отчёт по видео и macro/micro отдельно,
полнота предложений детектора отдельно. Стоимость =5FP+FN, FN включает
отказ и неправильную локализацию присутствующей цели. Это другой уровень
задачи, чем бинарная оценка готовых вырезок.

На непрерывных двух видео фиксируются последовательные серии FP, потери
TP→не-TP при видимой цели и восстановление не-TP→TP, а также возвраты
после интервалов без видимой аннотации. Это покадровый повторный поиск;
новое обучение трекера или улучшение оптического потока не заявляется.
Средняя скорость стендового прогона учитывает модельные стадии отдельно
от загрузки данных; подготовка кэшей не выдаётся за онлайн FPS.

Выбор последовательностей, кадров и ID не меняется по результатам.
Повторение фрагментов/похожих сцен отдельно учитывается при обсуждении
независимости. Синтетическое отсутствие цели не добавляется.
