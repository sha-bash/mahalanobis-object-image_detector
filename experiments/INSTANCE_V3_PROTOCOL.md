# Протокол диагностики и новой проверки от 11 октября 2026 года

Старый GMOT-тест после опубликованной оценки становится материалом разработки.
Его результаты не используются как новая независимая проверка. Исходные файлы
и модели v2 сохраняются. Ветка codex/instance-diagnostics-v3.

## Данные до вычисления признаков и оценок

Washington RGB-D Object Dataset, официальный evaluation ZIP: реальные физические
ID и отдельные видео при разных высотах камеры. Условия: только некоммерческое
исследовательское/образовательное использование; Lai et al., ICRA 2011.
https://rgbd-dataset.cs.washington.edu/dataset.html

Основной опыт: первые 12 категорий по алфавиту с минимум 6 ID, исключая категории
сцен bowl, cap, cereal_box, coffee_mug, soda_can, flashlight. В каждой категории
первые 6 ID по числовому номеру: 1–2 по порядку train, 3–4 validation, 5–6 test.
Для каждого ID берём первый кадр минимального номера видео как один референс;
из следующего по номеру видео — кадры в позициях floor((n-1)*q),
q=0, 1/3, 2/3, 1. Проверка наличия файлов проводится до оценивания; недостаток
данных не разрешает подменить ID по наблюдаемому качеству.
Съёмки разные, но установка и фон общие: это не доказательство переноса на
произвольную независимую сцену. Нужны 72 ID и 360 RGB-вырезок. Depth не используется.
Каждый запрос сравнивается с 8 кандидатами двух ID того же split/category:
4 positive, 4 negative. На test 24 запроса, 192 пары. Фон не удаляется по маске.

Обучение расширяется всеми 112 GMOT ID (560 старых вырезок, теперь development)
и 24 новыми train ID. ID новых validation/test в обучение не входят.
Неудачные описания: одна повторная попытка с прежним запросом, затем фиксированный
отказ текстового метода. Для комбинированного фильтра отсутствие описания означает
возврат к визуальному решению; это заранее заданная проверка полезности фильтра.

## Зафиксированные методы

Замороженные DINOv2-small и MiniLM/Qwen3.5:0.8b тех же ревизий, что в v2.
Базовые сравнения: SIFT и DINO-косинус. Текст: косинус, полная регуляризованная
ковариация; авторский MLP: косинус и Махаланобис. Визуальный MLP: те же две метрики.
MLP архитектура исходная 384→256→128→64, BatchNorm/GELU/dropout0.1.
Новая фиксированная тренировка: batch-hard triplet на L2-нормированном выходе,
margin0.2, Adam0.001, 30 эпох, seed2027. Блоки по категории/старому видео,
все 5 изображений каждого train ID; самый далёкий positive и ближайший negative
определяются только внутри обучающего блока. Никакого подбора seed по тесту.
Полная covariance Ledoit-Wolf+1e-4I по симметричным разностям train-пар одного ID.
Диагональная covariance — контроль в артефактах при доступном времени.

Основное сравнение: выбранный на validation визуальный метод против того же
метода с условной текстовой проверкой. Визуальный кандидат выбирается среди
DINO cosine, visual MLP cosine, visual MLP full Mahalanobis по минимальному FPR
при выполнении ограничения полноты; при равенстве выше recall, затем имя.
R* — среднее validation recall SIFT и DINO на максимальном macro-F1, затем
порог каждого метода минимизирует FPR при recall≥R*. Минимально полезный эффект:
строгое снижение FPR при test recall≥R* и без снижения test recall относительно
выбранного визуального метода. Допуск снижения полноты равен нулю.

Условная проверка применяется только к визуально принятым парам с расстоянием
выше уровня неоднозначности. Его варианты — квантили .0,.5,.75,1 положительных
validation-расстояний; текстовый порог берётся из validation-расстояний и варианта
«не отказывать». Выбор минимизирует FPR при recall≥R*. Равенства: меньше вызовов
текста, затем выше recall. Если выигрыш недостижим, выбирается отключение фильтра.
Не разрешено расширять сетку после просмотра теста. Фиксируется доля пар,
требующих текста; это оценка политики, не измеренное ускорение онлайн-системы.

## Метрики и статистика

Пары: precision/recall/FPR/F1, confusion matrix, PR, ROC, расстояния; macro по
категориям, отдельные ID и категории. Положительная доля здесь 1/2, в v2 1/4:
precision напрямую между опытами не сравнивается. Основной направленный sign test
по 12 категориям, условно на ненулевых разностях FPR; H0 вероятность улучшения
среди ненулевых изменений ≤1/2. Парный bootstrap по категориям для среднего
эффекта, 10000 повторов seed2027. Неотвержение H0 не подтверждает равенство.
Остальные сравнения разведочные. Все пороги сохраняются до оценки test.

## Целые сцены и отсутствие видимой цели

Дополнительный доменный перенос, не основание основной проверки гипотезы:
официальные desk_1, meeting_small_1 — validation; desk_2, table_small_1 — test.
Train не содержит категории этих сцен. Validation query IDs — объединение ID
двух validation-сцен; test query IDs — ID двух test-сцен минус validation IDs.
Объекты без эталона в ZIP не подменяются: явно исключаются до оценки и перечисляются.
Для каждого scene/query — до 4 равномерных кадров присутствия и 4 отсутствия
видимой аннотированной цели, независимо от предсказаний. Разметка источника
задаёт видимое присутствие; отсутствие разметки не доказывает физического
отсутствия скрытого объекта. Эталон из turntable-съёмки, начальной рамки нет.
YOLOv8n640/conf.25/NMS.45/max20 и тот же визуальный выбор + условный текст.
Пороги переносятся из опыта с вырезками: трудность переноса явно сообщается.
TP требует IoU≥.5. Неверная рамка при наличии цели даёт FP+FN, отказ даёт FN.
IoU пропуска=0. При отсутствии видимой цели выдача рамки даёт FP, отказ TN.
Физический выход/возврат и непрерывный трекинг не заявляются по редким кадрам.

## Воспроизводимость

CPU4threads, модели по очереди, изображения batch≤8. Контрольные точки после
описаний и признаков; локальные веса/изображения не коммитятся. HTTP Range читает
только нужные файлы ZIP, проверяет Content-Range, размер, ZIP CRC и SHA256 каждого
сохранённого изображения. Протокол, manifest, параметры и хеши фиксируются в Git.
Графики русские. Документы v2 не переписываются; новый отчёт и тезисы — отдельно.
