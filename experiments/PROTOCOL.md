# Протокол 2026-10-02-v1

Зафиксирован до новых запусков и до подбора порогов. Старые результаты уже известны.
`protocol.json` задаёт вопросы, seed, сетку порогов и критерий выбора.
Демонстрационное видео никогда не становится тестом, в том числе после доразметки.

## Вход и выбор эталона

Один экземпляр, одно изображение, всё видео с нулевого кадра. Рамка на видео не
предоставляется. Разрешено один раз выделить объект **на эталонном изображении**.
Выбирать первый по времени резкий кадр, на котором видно не менее 80% объекта,
до запуска методов. Не выбирать эталон по достигнутому IoU. Хранить исходник,
crop, идентификатор камеры/съёмки, время, SHA256 и автора выбора.
Эталон из отдельной съёмки — основной протокол; эталон из той же сцены — отдельный.
Трекеры с начальной GT-рамкой допускаются только в отдельном oracle-init протоколе.

## Разбиение и минимальные данные

Предлагаемый минимальный пилот для тезисов: 24 целевых экземпляра, 48 независимых
видеосъёмок, не менее двух на экземпляр. 8/8/8 экземпляров для train/validation/test,
16/16/16 видео соответственно. Дополнительный эталон отдельной съёмки для каждого.
Для каждого запроса тест включает положительную запись и запись без цели с похожей
техникой. Если в кадрах встречаются другие размеченные экземпляры, все связанные
видео и идентичности объединять в один cluster и целиком переносить в один split.
Общее число независимых кластеров может оказаться меньше числа объектов.
24 объекта — практический нижний ориентир пилота, не обоснование статистической мощности.
Для отказа от обучаемой метрики train можно не использовать, но не переносить его
в test после просмотра результатов. Сложности разнести по последовательностям:
масштаб/ракурс, похожие машины, отсутствие, перекрытие, выход/возврат.

Для журнала: ориентир 100–200 экземпляров, 300–600 съёмок, несколько камер/мест,
30+ независимых тестовых кластеров, отдельные домены и заранее оценённая мощность
по разбросу эффекта между кластерами пилота. Не называть аугментации независимыми
съёмками. Соседние фрагменты одной записи принадлежат одному video_id и split.

## Разметка

Файл JSON содержит `frames`: `frame` (0-based), `status` (`present`, `absent`,
`ignore`), `size` [width,height], при present `bbox_xyxy`, а также
`distractor_boxes`, `distractors_complete`. Все рамки — half-open xyxy в исходных
пикселях. Изменение размера учитывается отдельно по x и y.
Absent означает подтверждённое отсутствие целевого экземпляра, а не отсутствие
записи в файле. Полное перекрытие без локализуемой цели маркировать ignore;
частичное — present с рамкой видимой части (одна конвенция во всех split).
Вводить также видимость и теги сложности для последующего стратифицированного анализа.
Разметчик не смотрит предсказания. Спорные идентичности и интервалы проверяет второй
разметчик; сохранять согласование. Старый COCO адаптер использует только 391 явную
рамку; другие кадры остаются неизвестными. Происхождение старой разметки не установлено.

## Сравнения

G: исходный SIFT/RANSAC + NCC + поток. S: ровно G + исходная независимая VLM/SBERT
проверка. FG/FS: маска GrabCut в SIFT, NCC и точках потока; тот же контур рамки,
пороги и расписание поиска, с семантикой и без неё. Маска может ошибаться; записывается
факт её использования. Это гипотеза уменьшения зависимости от фона.
Внешний простой метод: OpenCV TM_CCOEFF_NORMED по полному кадру, один масштаб эталона,
порог 0.8 до пилотной валидации; без начальной рамки. Это слабый классический
reference-only baseline, не современный ReID/SOT и не доказательство SOTA.
Выдавать максимум одну рамку на кадр. Один и тот же декодер, размер, CPU threads=4.
Для времён сравнивать одинаковый экспорт и полные таймеры; template пока без экспорта
видео, поэтому его runtime не сопоставлять напрямую. Основные прогоны последовательно.

Сначала общий пул кандидатов для оценки семантики с независимой разметкой true/false
identity, затем полные online прогоны. Отклонение меняет дальнейшую траекторию:
пороговую кривую по трём старым решениям нельзя объявлять кривой всей системы.
Сохранять crop/его hash, рамку, индекс кадра, текст, признаки, score, решение,
время, cache status и причину отказа. У старых проверок нет рамок в checks;
они восстанавливаются по frame row только для принятых кандидатов.

Для текстовых и визуальных признаков отдельно: cosine vs диагональная shrinkage
ковариация внутриклассовых разностей на train, регуляризация выбирается validation.
Те же пары и L2-нормированные признаки. Не оценивать ковариацию на одном эталоне,
не смешивать межклассовую дисперсию с внутриклассовой. Полная ковариация при малом n
не оправдана. Изотропный вариант d²=200(1−cos) — эквивалентная параметризация.
При tau=6 эквивалентный порог cosine similarity=0.82.

## Метрики и выбор

Основная локализация: TP при present и IoU>=0.5; отказ/неверная рамка даёт FN.
Любая выданная неверная рамка даёт FP; неверная рамка при present даёт одновременно
FP и FN. Precision=TP/(TP+FP), recall=TP/N_present. mIoU включает нули пропусков.
Absent FPR=число выданных рамок/N_absent. Wrong-instance — неверная рамка с IoU>=0.5
с размеченным отвлекающим экземпляром; отсутствие такой разметки не означает ноль.
При совпадении с target и distractor приоритет target; неоднозначность отметить в GT.
Выдавать также долю кадров отказа, потери success→failure в непрерывном present
интервале, recovery failure→success, задержку первого успеха после входа цели,
число входов без успеха (цензурированные), задержку после перекрытий отдельно.

Рабочий порог: на validation минимизировать absent FPR при recall>=0.70, при
равенстве — больший recall, затем меньшее время. Если нет подходящего метода,
так и сообщить. Test запускать один раз с замороженной конфигурацией. Изменения
после test требуют нового теста. Дополнительно кривые recall–FPR и precision–recall,
но не выбирать по ним новую конфигурацию на test.

Отчёт по каждому видео, pooled frame counts и macro-average по видео; отсутствие
знаменателя представлять null. Парный bootstrap 10 000 повторов по независимым
cluster_id с одинаковой выборкой для двух методов. При одном кластере CI не строить;
при <10 кластерах явно называть интервалы нестабильными, без выводов о значимости.
Для журнала — иерархический анализ по объекту/сцене. Скорость: декодирование,
подготовка, геометрия, VLM, embedding, экспорт и полное wall time; 3 повтора cold/warm
раздельно. Пиковая память дерева процессов и Ollama отдельно; main-process RSS не
выдавать за полную память модели.
