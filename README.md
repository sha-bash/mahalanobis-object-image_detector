# Поиск заданного экземпляра объекта по изображению

Исследовательский проект для поиска конкретного физического объекта по одному
эталонному изображению. Вход — фотография объекта и видео; выход — рамка цели
либо отказ. Совпадения категории недостаточно для подтверждения экземпляра.

## Два режима

- **Базовый видеоконвейер:** SIFT/RANSAC → независимые описания VLM →
  Sentence-BERT → расстояние Махаланобиса. Между проверками используется
  оптический поток. Запуск через `run.ps1` или `run.py`.
- **Экспериментальный контур:** признаки DINOv2, условная текстовая проверка
  Qwen → MiniLM → обучаемый MLP, сравнение косинуса и регуляризованного
  Махаланобиса. На полных кадрах YOLOv8n предлагает кандидатов.
  Запуск через исследовательские скрипты в `scripts/`.

Обучаемый MLP не включается автоматически в базовом режиме. Универсальность
поиска и преимущество текстовой проверки — исследовательские гипотезы.

## Быстрый запуск Windows

Проверенная среда: Windows x64, Python 3.11, CPU, около 8 ГБ RAM.
При первом запуске нужны интернет и несколько ГБ свободного диска.
Обработка на таком CPU не рассчитана на реальное время.

```powershell
git clone https://github.com/sha-bash/mahalanobis-object-image_detector.git
cd mahalanobis-object-image_detector
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Программа запросит пути к фото и видео. При необходимости загрузчик установит
Python через WinGet, создаст `.venv`, установит CPU-зависимости и подготовит
Ollama, Qwen3.5:0.8b и all-MiniLM-L6-v2. Если WinGet недоступен, установите
Python 3.11 самостоятельно. Веса сохраняются только локально.

```powershell
.\run.ps1 -Reference 'D:\Data\reference.jpg' -Video 'D:\Data\video.mp4'
.\run.ps1 -SetupOnly
```

Эталон должен содержать крупно изображённый объект. Параметр
`-ReferenceBox @(x1,y1,x2,y2)` выделяет объект на необрезанном фото.
При подготовленной среде можно использовать:

```powershell
python run.py --reference reference.jpg --video video.mp4
python run.py --help
```

Каждый запуск создаёт каталог `reports/instance_<дата_время>/` с видео с рамками,
`results.json`, семантическими расстояниями и контрольными изображениями.
Наличие выданной рамки само по себе не означает правильного обнаружения.

## Структура и политика хранения

- `src/moid/` — поиск, сопровождение, семантическая проверка и метрики.
- `src/mcd/` — обучаемый проектор и метрика.
- `configs/`, `requirements/`, `tests/` — настройки, зависимости и тесты.
- `scripts/` — подготовка данных, запуск, оценка и построение отчётов.
- `annotations/instances.json` — разметка демонстрационной записи: результат
  трекера, проверенный человеком. Это не независимый тест.
- `experiments/` — протоколы и команды воспроизведения.
- `experiments/evidence/` — в Git остаются только входные манифесты
  и сведения об источниках. Остальные файлы здесь создаются скриптами и игнорируются.
- `data/refs/`, `data/search/`, `experiments/local/` — локальные фото и видео.
- `models/` — локальные веса; `reports/`, `output/` — локальные результаты.

Предсказания, извлечённые признаки, обученные веса, VLM-описания, журналы,
графики, отчёты и выполненные ноутбуки не входят в актуальное дерево Git.
Удаление из индекса не удаляет локальные копии. Прежние результаты доступны
в локальной исследовательской ветке `codex/russian-illustrated-report`
(коммит `913c869`); исходный базовый вариант — `5552bc2`.
Ветка очистки не переносит промежуточные коммиты с артефактами на GitHub.
Секреты храните в локальном `.env`, используя `.env.example` как пример.

## Эксперименты

Начните с [команд воспроизведения](experiments/INSTANCE_V4_REPRODUCE.md)
и [описания входных данных](experiments/INPUT_DATA.md). После чистого клонирования
нужно пересчитать признаки предварительных серий; готовых признаков в Git нет.

- [Протокол сравнения на изображениях](experiments/INSTANCE_V4_PROTOCOL.md).
- [Протокол переноса на видео](experiments/INSTANCE_V4_VIDEO_PROTOCOL.md).
- [Источники публичных данных](experiments/DATASETS.md).
- [Протокол обучения MLP](experiments/MLP_PROTOCOL.md).

Разбиение выполняется по экземплярам. Пороги выбираются на validation,
ковариация и MLP оцениваются без тестовых объектов. Перед оценкой создаётся
локальный `pretest_checkpoint.json` с SHA-256 настроек. При изменении настроек
скрипт отказывается молча заменять контрольную точку. Это не внешняя регистрация
эксперимента. Автоматических коммитов результатов нет; повторно изученный тест
нельзя считать новым.

Оцениваются полнота на кадрах присутствия, ложные принятия, IoU с нулём для
пропусков, время и стоимость ошибок. Сравнивать методы следует на одинаковых
кандидатах и при ограничении потери полноты, заданном до просмотра теста.

## Разработка

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.14.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -c requirements/cpu.txt '.[dev]'
.\.venv\Scripts\python.exe -m ruff check src tests scripts run.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m build
```

Фиксированная экспериментальная среда: `requirements/mlp-cpu-lock.txt`.
Тесты не требуют скачивания публичных видеонаборов. Linux/macOS не проверены
полным сквозным запуском; исследовательские обёртки ориентированы на Windows.

## Ограничения и лицензии

Описание может терять мелкие признаки экземпляра. Текстовый фильтр не
восстанавливает цель, для которой детектор не предложил рамку. Эталон из того
же видео и эталон из независимой съёмки — разные протоколы.
В базовом режиме Σ = 0,01I для нормированных векторов эквивалентна
масштабированному евклидову расстоянию и порогу косинуса; это не самостоятельный
выигрыш метрики Махаланобиса.

Проектор перенесён из [mahalanobis-concept-drift](https://github.com/sha-bash/mahalanobis-concept-drift),
его лицензия сохранена в `src/mcd/projection/LICENSE.upstream`.
Модели, зависимости и наборы имеют собственные условия использования.
Скрипт загрузки не предоставляет права перераспространения исходных данных.
